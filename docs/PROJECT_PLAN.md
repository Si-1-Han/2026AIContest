# 프로젝트 계획서 — 한세 3D 캠퍼스 (가칭)

> 2026-2 한세대학교 AI Contest 출품작
> 작성일: 2026-11-03 · 상태: 기획 확정 / 개발 착수 전

---

## 1. 한 줄 소개

**한세대학교 캠퍼스를 게임처럼 화려한 3D로 재현하고, "○○관 가는 길 알려줘"라고 말하면 AI가 길을 찾아 카메라가 경로를 따라 날아가는 웹 서비스.**

## 2. 배경과 목표

### 2.1 문제

- 네이버·카카오·구글 지도는 캠퍼스 내부(건물 입구, 보행로, 층·강의실)를 거의 알려주지 않는다.
- 한세대는 경사지에 건물이 흩어져 있어 신입생·방문객·수험생이 건물을 찾기 어렵다.
- 학교 홍보 측면에서도 "캠퍼스를 둘러보는 경험"을 온라인으로 줄 수단이 없다.

### 2.2 목표

| 구분 | 목표 |
|---|---|
| 콘테스트 | 34개 팀 중 **"이건 저 팀만 할 수 있다"** 는 인상. 비주얼·사운드·스토리텔링으로 디자인 계열 심사위원도 압도 |
| AI 활용 | ① 제품 안의 AI(자연어 길안내) ② 개발 전 과정의 AI 활용을 **수치로** 증명 |
| 커리어 | 수상 여부와 무관하게 포트폴리오로 쓸 수 있는 완성도. 학교 홈페이지에 링크될 수준 |

### 2.3 교수님 피드백 반영 (2026-10-28 토의)

1. **정적 배포로 충분하다.** 무거운 서버 대신 정적 호스팅(Vercel 등)과 목(mock) JSON 데이터를 쓰되, "언제든 편집·확장 가능"하다는 것을 샘플 기능으로 보여준다.
2. **화려하게.** 웅장한 오프닝, BGM과 효과음(AI 생성 사운드), 영상처럼 보이는 연출을 넣는다.
3. **AI 활용량을 숫자로.** 사용한 프롬프트·토큰 총량, A4 환산 분량 등을 요약해 제출한다.
4. **평이한 주제는 피한다.** 상을 못 받더라도 커리어가 되는 결과물을 목표로 한다.
5. **AI 코딩 도구에 투자한다.** Claude Code와 Codex를 적극 활용한다.

## 3. 핵심 기능

우선순위: **P0** = 이게 없으면 데모가 성립하지 않음 · **P1** = 수상을 노리는 차별화 요소 · **P2** = 시간이 남으면

| # | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| F1 | 3D 캠퍼스 씬 | 건물 11개 동을 층수 기반으로 입체화. 지면·보행로·나무·하늘을 스타일라이즈드 로우폴리로 표현 | P0 |
| F2 | 시네마틱 인트로 | 로고 → 하늘에서 캠퍼스로 하강 → 건물이 땅에서 솟아오르는 애니메이션 + BGM | P0 |
| F3 | 건물 인터랙션 | 호버 시 하이라이트, 클릭 시 카메라 비행과 정보 패널(용도·주요 시설·층 정보) | P0 |
| F4 | 길찾기 | 출발지·도착지 선택 → 보행로 그래프에서 A* 탐색 → 빛나는 경로 라인 + 경로를 따라가는 카메라, 예상 소요 시간 표시 | P0 |
| F5 | AI 길안내 챗봇 | 자연어 입력("학생회관에서 이공관 어떻게 가?") → 출발지·목적지 인식 → F4 실행. API 장애 시 규칙 기반 폴백 | P0 |
| F6 | 정적 배포 | Vercel(정적 사이트 + 서버리스 함수 1개)로 공개 URL 제공 | P0 |
| F7 | 층 분해 뷰 | 건물 선택 시 층이 위아래로 벌어지며 층별 강의실 표시 | P1 |
| F8 | 자동 캠퍼스 투어 | 미리 정한 동선으로 카메라가 순회하고 나레이션(TTS)과 자막 재생. **발표 시연용** | P1 |
| F9 | 분위기 전환 | 낮/노을/밤 조명 전환. 밤에는 창문 발광과 블룸 효과 | P1 |
| F10 | 사운드 디자인 | 상황별 효과음(클릭, 비행, 도착)과 BGM, 음소거 토글 | P1 |
| F11 | AI 활용 대시보드 | 개발에 쓴 AI 사용량(토큰, 세션, A4 환산)을 시각화한 `/stats` 페이지 | P1 |
| F12 | 편집 모드 | 건물 정보·이벤트 마커를 화면에서 수정하고 JSON으로 내보내기(목 데이터, localStorage) | P2 |
| F13 | 계절 효과 | 벚꽃·눈 파티클 | P2 |
| F14 | 모바일 대응 | 터치 조작, 저사양 품질 프리셋 | P2 |

## 4. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 빌드 | Vite + React + TypeScript | 빠른 개발 서버, 타입 안정성, AI 코딩 도구와의 궁합 |
| 3D | three.js, @react-three/fiber, @react-three/drei | 지도 앱 수준을 넘는 연출 자유도, 지도 토큰 불필요 |
| 이펙트 | @react-three/postprocessing (Bloom, AO, Vignette) | "화려함"의 핵심 |
| 카메라 연출 | drei `CameraControls` + GSAP | 비행·투어 시퀀스 |
| 상태 관리 | zustand | 씬과 UI 간 상태 공유 |
| UI | Tailwind CSS | 오버레이 UI를 빠르게 구성 |
| 사운드 | howler.js | BGM·효과음 관리 |
| 길찾기 | 자체 A* (보행로 그래프 JSON) | 의존성 최소화, 경사로·계단 가중치 조절 |
| AI 챗봇 | Vercel Serverless Function → LLM API(경량 모델, function calling) | API 키 은닉. 응답은 구조화된 JSON 액션 |
| 나레이션 | Web Speech API 또는 사전 생성 TTS 음원 | 무료, 오프라인 대비 |
| 배포 | Vercel, GitHub Actions(빌드 확인) | 정적 배포 + 함수 1개 |

> 참고 프로젝트 HMH는 Mapbox GL `fill-extrusion` 기반이다. 우리는 **차별화를 위해 three.js로 씬을 직접 구성**하고, HMH의 데이터(건물 외곽선·층·강의실)만 원작자 허락을 받아 재사용한다.

## 5. 시스템 구성

```
┌──────────────────────── Browser (정적 사이트) ────────────────────────┐
│                                                                      │
│  UI Overlay (React)            3D Scene (R3F)                        │
│  ├ 검색/출발·도착 선택          ├ Campus (지면·보행로·나무·하늘)       │
│  ├ 건물 정보 패널               ├ Buildings (extrude, 층 분해)         │
│  ├ AI 채팅창 ───────┐           ├ RouteLine (발광 경로 + 파티클)       │
│  └ HUD/음소거       │           ├ Effects (Bloom/AO)                  │
│                     │           └ CameraDirector (비행·투어)          │
│        zustand store (선택 건물, 경로, 모드, 시간대)                  │
│                     │                                                │
│   data/*.json  ◀────┼──── campus.json · rooms.json · paths.json      │
└─────────────────────┼────────────────────────────────────────────────┘
                      ▼
         /api/guide (Vercel Function) ──▶ LLM API
         입력: 사용자 문장 + 건물 목록(id·별칭)
         출력: { action: "navigate", from, to, message }
         실패 시 → 클라이언트 별칭 매칭 폴백
```

### 5.1 AI 길안내 흐름

1. 사용자: "도서관에서 이공관 가는 길 알려줘"
2. `/api/guide`: 시스템 프롬프트에 건물 ID·별칭 목록을 넣고, function calling으로 `navigate(from, to)`, `focus_building(id)`, `start_tour()` 중 하나를 선택하게 한다.
3. 클라이언트: 받은 액션을 실행한다. 경로를 탐색하고, 카메라가 비행하며, 챗봇이 안내 문장을 출력한다(TTS 선택).
4. 출발지가 없으면 "현재 위치(정문)"를 기본값으로 쓰거나 되묻는다.
5. 안전장치: 일일 호출 한도, 입력 길이 제한, 키는 서버 환경변수에만 둔다.

## 6. 데이터 설계

### 6.1 출처

| 데이터 | 출처 | 라이선스·조건 |
|---|---|---|
| 건물 외곽선 | OpenStreetMap (HMH `buildings.geojson`에 포함) | ODbL — **출처 표기 필수** |
| 층·강의실 폴리곤 | HMH `rooms.json` (wjdgh0628/open_source_5) | LICENSE 없음 → **원작자 허락 후 사용, README에 출처 표기** |
| 보행로 그래프 | 직접 제작 (OSM footway 참고 + geojson.io 수작업 보정) | 우리 팀 |
| 건물 설명·별칭 | 학교 홈페이지 등을 참고해 직접 작성 | 우리 팀 |

### 6.2 좌표계

- 기준점: `126.95336, 37.34524` (캠퍼스 중심)
- 위경도를 로컬 미터 좌표로 변환하는 등장방형 근사:
  `x = (lon - lon0) · cos(lat0) · 111320`, `z = -(lat - lat0) · 110540`
- 변환은 `scripts/`의 Node 스크립트에서 한 번 수행하고, 결과를 `public/data/*.json`으로 저장한다.

### 6.3 스키마 (초안)

```jsonc
// campus.json
{
  "origin": [126.95336, 37.34524],
  "buildings": [{
    "id": "main",
    "name": "본관",
    "aliases": ["본관", "대학본부"],
    "levels": 9, "basements": 1,
    "footprint": [[x, z], ...],        // 로컬 미터
    "floorHeight": 4.5,
    "entrances": ["n_main_1"],          // paths.json 노드 ID
    "description": "...",
    "facilities": ["총장실", "..."]
  }]
}

// paths.json — 보행로 그래프
{
  "nodes": [{ "id": "n_gate", "x": 0, "z": 0, "y": 0, "type": "gate|junction|entrance|stairs" }],
  "edges": [{ "a": "n_gate", "b": "n_1", "kind": "walk|stairs|slope" }]
}
```

## 10. AI 활용 전략 (평가 어필 포인트)

| 단계 | 활용 | 기록 방법 |
|---|---|---|
| 기획 | 회의 녹취 요약, 요구사항 정리, 계획서 초안 | `docs/ai-log/`에 세션 요약 |
| 개발 | Claude Code·Codex로 코드 작성·리뷰·디버깅 | 세션별 사용량(토큰·프롬프트 수) 기록 |

- **기록 규칙:** 작업 세션이 끝날 때마다 `docs/ai-log/YYYY-MM-DD-이름.md`에 *무엇을 시켰고, 무엇을 얻었고, 사용량은 얼마인지* 3줄을 남긴다.
