# 캠퍼스 투어 외관 모델

## 사용자 화면에 따른 부지 수정 (2026-11-16)

- 본관 1층 진입로의 난간·옹벽은 도로 밖(v=16.2m)에서 끝낸다.
- 1층 외벽 앞 지면은 낮게 개방하고, 2층 계단 옆에만 작은 두 식재 구역과
  관목 10개를 둔다. 넓은 조경 언덕으로 1층을 가리지 않는다.
- 대학원관 옆은 평지 위 원형 분수대와 본관을 향한 교명 표지판이다.
  직사각형 계단 단상은 없으며, 나무 네 그루를 바깥에 띄워 놓는다.
- GEMI관→영비관의 차도는 7m, 보도는 양쪽 1.8m인 직선이다.
  보도는 주차장 진입부 두 곳만 열며, 주차장 내부 경로로 분기시키지 않는다.
- 영비관 앞 중앙 주차장에는 완전한 2.6×4.8m 칸을 일정하게 도색한다.
  경계에서 잘린 주차선과 고립된 인도·연석·점자블록은 만들지 않는다.

`npm --prefix web run test:site-details`는 실제 난간·옹벽 메시의 차도 겹침,
1층 앞 지면, 식재 범위, 분수대 평지와 표지판 방향, 직선 보도와 주차선을 검사한다.

## 도로·인도 평탄화 (2026-11-16)

`pavementGrade.ts`에서 차도·인도·연석·주차선의 기준 경사를 공유한다.
정문 오르막 끝과 본관 2층 계단 아래·본관 측면/북측 주차장은 같은 높이로
이어지며, 음악관 서측 오르막은 주차장에 닿기 전에 수평으로 끝난다.
주차장 경계는 도로 삼각형과 분리해 실제 포장 메시도 완전히 수평이다.
지형 테셀레이션 후 법선을 연결해 삼각형마다 접혀 보이던 음영을 제거했다.

`campus-pavement.blend`는 실제 웹과 같은 좌표를 사용하는 전체 포장면과
본관 전용 진입로의 편집·검토 원본이다. `drain-grate.glb`는 Blender에서 만든
3mm 베벨·실제 격자 틈·체결 볼트를 가진 배수구이며 웹에서 경사에 맞춰
인스턴싱한다. 웹의 노면 메시를 Blender에서 다시 지형에 투영하지 않는다.

```sh
npm --prefix web run models:roads -- --blender /path/to/Blender
npm --prefix web run test:pavement
```

`pavement-manifest.json`의 SHA-256과 소스 리비전으로 웹/Blender 원본의
일치를 검사한다. 진입로의 내리막, 차도와 인도의 횡단 경사, 실제 주차장
삼각형의 수평성은 `test:pavement`로 회귀 검증한다.

## 본관·음악관 사진 반영 (2026-11-16)

Blender 4.5.16 LTS로 편집 원본과 11동의 압축 GLB를 다시 생성했다.
본관·음악관도 최신 GLB를 사용하며 출입구·계단·유리 계단실이 공유 명세와 일치한다.
도로·인도·식재·경사로는 웹의 부지 지오메트리로 관리한다.

- 2층 정문을 기준으로 1층 선큰 입구와 운동장 쪽 3층 진입로를 연결한다.
- 정면의 긴 파란 판을 주차장 쪽 저층동 유리 계단실로 교체한다.
- 계단 옆 식재·본관 측면 주차장·3층 입구 옆 공원은 `MainGrounds.tsx`와
  `mainBuildingAccess.ts`에서 관리한다.
- 운동장 서쪽 보행로는 `fieldWalk.ts`, 명패 뒤 원형 분수대는
  `CampusFountain.tsx`에서 관리한다.
- 정문 옆 식재는 `Shrubs.tsx`의 줄기 없는 둥근 관목이다. 잎의 색·노멀 맵과
  세밀한 수관 메시를 사용한다.
- 1층 입구와 계단은 `terrainCuts.ts`에서 잔디 삼각형을 잘라 문 앞을 개방한다.
- 3층 입구는 직선 완경사 뒤 짧은 계단으로 연결하며, 공원은 계단 아래 높이다.
- 음악관 서측 1층 중앙 입구와 지도 네모 전체의 주차장·인도는
  `musicForecourt.ts`에서 관리한다. 운동장 뒤로 이어지던 잘못된 연결은 삭제했다.
- 잔디는 모든 차도·인도·전용 진입로 경계에서 잘라 포장면을 뚫지 않게 한다.

`npm --prefix web run test:main-site`는 새 동선의 연결과 실제 보행면/지형 충돌을
검증한다. `test:tour-art`는 최신 원본과 GLB 일치 및 실제 압축 메시를 검사한다.

`campus-exteriors.blend`는 11개 건물을 건물별 컬렉션으로 나눈 편집 원본이다.
`previews/<건물 ID>.png`는 이전 Blender Cycles 검토 이미지다. 이번 재생성에는
`--preview`를 사용하지 않았으므로 최신 검토에는 웹 화면이나 `.blend`를 사용한다.
`reviews/2026-11-16/`에는 실제 웹 화면에서 확인한 정문·1층·3층·음악관 주차장 이미지가 있다.
웹용 압축 모델은 `web/public/models/tour/*.glb`에 저장한다.

## 반영한 디테일

- 사방 알루미늄 창틀, 유리와 창틀의 깊이 차이, 돌출 창턱, 벽체 몰딩
- 노출 테라스·옥상 난간, 처마와 차양, 사진에 따른 건물별 재료와 지붕
- 모서리 베벨과 가중 표면 법선
- 석재·벽돌의 색/노멀/거칠기 맵, 불투명 외관 유리의 클리어코트

층별 윤곽과 위치는 기존 지도 데이터에서 가져온다. 창문 배치·재료·차양 등의
세부 치수는 제공된 사진을 참고한 근사값이다. 사진측량·실측 기반 정밀 복원이나
보이지 않는 면의 정확도를 보장하는 모델은 아니며, 실내는 포함하지 않는다.

## 다시 생성

Blender 4.5 LTS를 사용할 수 있는 환경에서 저장소 루트에서 실행한다.

```sh
npm --prefix web run models:tour -- --blender "/Applications/Blender.app/Contents/MacOS/Blender" --preview
npm --prefix web run test:tour-art
```

`--preview`를 빼면 검토 이미지를 다시 렌더링하지 않는다. `BLENDER_EXECUTABLE`
환경변수로 실행 파일을 지정할 수도 있다. `.cache/tour-models`는 중간 산출물이다.

웹과 Blender는 `web/src/scene/tour/exteriorSpec.ts`의 같은 외관 명세를 사용한다.
생성기는 공유 명세와 PBR 맵을 읽고 베벨·법선·삼각화를 적용한 다음 Draco 압축
GLB를 내보낸다. `manifest.json`에는 원본 리비전과 각 파일의 SHA-256이 들어간다.
검증은 실제 압축 메시를 디코딩하여 좌표계·재질·파일 무결성도 확인한다.

웹에서는 130m 안의 건물 모델만 로드하고, 로딩 중 또는 실패한 경우에도 절차적
외관을 계속 표시한다. 디코더와 재질은 모두 로컬에서 제공하여 CDN이나 API 키가
필요 없다. `.blend`에 텍스처를 패킹했으므로 임시 생성 경로에 의존하지 않는다.

원본 지도 데이터의 기존 출처/ODbL 표시는 유지한다. 사용자 제공 사진은 외관의
참고로만 사용했으며 모델에 사진 텍스처를 복제하지 않았다. Draco 디코더의
Apache-2.0 고지는 `web/public/draco`에 동봉했다.
